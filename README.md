# Gather - Εφαρμογή Διαχείρισης Εκδηλώσεων και Ηλεκτρονικών Κρατήσεων 

Η παρούσα διαδικτυακή εφαρμογή αναπτύχθηκε στα πλαίσια πανεπιστημιακής εργασίας[cite: 3]. Αποτελεί ένα ολοκληρωμένο σύστημα διαχείρισης εκδηλώσεων και ηλεκτρονικών κρατήσεων θέσεων, το οποίο καλύπτει ολόκληρο τον κύκλο ζωής μιας εκδήλωσης, από τη δημιουργία της έως την παραγωγή προσωποποιημένων συστάσεων[cite: 4].

**Σημείωση για τα Δεδομένα (Datasets):** 
Ο κώδικας επεξεργάζεται τα αρχεία δεδομένων της Gather Application. Λόγω μεγέθους, τα πλήρη αρχεία (εκατοντάδων MB) δεν περιλαμβάνονται σε αυτό το repository. Στον φάκελο `gather_application/rel_event_csvs/` έχουν τοποθετηθεί μικρά δείγματα (samples) των 100 γραμμών για την επιβεβαίωση της λειτουργίας του κώδικα. Όλες οι αναλυτικές πληροφορίες σχεδιασμού και οι αρχιτεκτονικές αποφάσεις βρίσκονται στο αρχείο **Αναφορά_Εργασίας.pdf**.

## 🛠️ Τεχνολογίες (Tech Stack)
Η εφαρμογή ακολουθεί σύγχρονη αρχιτεκτονική client-server[cite: 4]:
* **Frontend:** Single Page Application (SPA) αναπτυγμένο με React και TypeScript[cite: 4].
* **Backend:** REST API αναπτυγμένο σε Python με το framework FastAPI[cite: 4].
* **Βάση Δεδομένων:** PostgreSQL με χρήση του SQLAlchemy ORM[cite: 4].
* **Deployment:** Docker Compose και Caddy ως reverse proxy (με υποστήριξη HTTPS)[cite: 4].

## 👥 Ρόλοι Χρηστών
Το σύστημα υποστηρίζει αυστηρό Role-Based Access Control (RBAC)[cite: 4] με 4 διακριτούς ρόλους[cite: 16]:
1. **Επισκέπτης:** Πλοήγηση και αναζήτηση εκδηλώσεων χωρίς σύνδεση[cite: 16].
2. **Συμμετέχων:** Πραγματοποίηση κρατήσεων, ανταλλαγή μηνυμάτων, προβολή συστάσεων[cite: 16].
3. **Διοργανωτής:** Δημιουργία, δημοσίευση και ακύρωση εκδηλώσεων, διαχείριση κρατήσεων[cite: 16].
4. **Διαχειριστής (Admin):** Έγκριση νέων χρηστών και εξαγωγή δεδομένων σε μορφή XML/JSON[cite: 16, 33].

## ✨ Βασικά Χαρακτηριστικά
* **Ασφαλείς Κρατήσεις (Concurrency):** Υλοποίηση ατομικών ενημερώσεων (atomic updates) στη βάση δεδομένων για την αποφυγή υπερκράτησης (overbooking) κατά την ταυτόχρονη πρόσβαση πολλών χρηστών[cite: 28].
* **Σύστημα Συστάσεων:** Προσωποποιημένες προτάσεις εκδηλώσεων μέσω αλγορίθμου **Biased Matrix Factorization**, ο οποίος εκπαιδεύεται από την έμμεση ανατροφοδότηση (implicit feedback) των χρηστών (προβολές και κρατήσεις)[cite: 4, 36, 38].
* **Επικοινωνία:** Εσωτερικό σύστημα μηνυμάτων (inbox/sent) μεταξύ διοργανωτών και συμμετεχόντων[cite: 32].
* **Ασφάλεια:** Αυθεντικοποίηση με JSON Web Tokens (JWT) και κρυπτογράφηση κωδικών με τον αλγόριθμο Argon2id[cite: 4, 42].
